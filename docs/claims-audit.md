# Claims audit (README.md)

Every factual claim in README.md, and the evidence behind it. Audit date: 2026-09-29.

Evidence types:
- **test**: a pytest test. The M3 audit run had 107 passed; after the follow-up below, 108 passed, with atlas-local up.
- **demo**: a demo check. `.gax/demo-results/<name>.json` is regenerated by `gax demo run <name>` and is not committed; sanitized copies from the recorded run are in [docs/evidence/](evidence/) and the recorded values are in docs/failure-semantics.md.
- **findings**: an entry in docs/m0-findings.md, docs/m1-findings.md or docs/failure-semantics.md.
- **M3 run**: a command executed during this audit (see "Commands verified in M3" below).
- **code**: inspection only, with no test or demo. These rows are listed so the gap is visible.
- **author**: the author's own account (event attendance, talk content, affiliation). Nothing in the repo can verify it.

## Claims removed or reworded during the audit

1. "Temporal protects against losing an approval wait" became "approval waits with no deadline". No run restarted the worker during an approval wait. The failure-semantics §7 claim that the wait "outlives worker restarts" is now marked as not demonstrated.
2. "Setting `KEYCARD_ZONE_URL` makes the worker refuse to start" became "`build_broker` raises `NotImplementedError`". The test covers `build_broker`, not worker startup.
3. "Only `voyage_429` calls a paid API" became "demos make no LLM or Voyage calls except `voyage_429`". That matches the failure-semantics wording.
4. "Activity heartbeating in remediation" became "activity heartbeating". That matches m0-findings.
5. The retrieval-failure limitation now says the path is not exercised by a test or demo, and it was added to NOT VERIFIED.
6. The diagram now shows `snapshot_state` and `verify_outcome` also fetching credentials. That matches row 17. The earlier draft showed only `execute_action`.

## Closed after the audit (2026-09-29)

1. Durable approval wait surviving a worker restart (removed item 1 above). New demo `approval_worker_restart` kills the real worker at `AWAITING_APPROVAL`, starts a new worker, and approves. PASS 11/11; failure-semantics §12. README row 18 and the failure matrix now cite it.
2. Retrieval failure that proceeds without context (removed item 5 above). New integration test `test_retrieval_error_proposes_with_empty_context_and_policy_still_gates`. README limitation reworded; the path is test-covered, not demo-covered.
3. The README quickstart no longer names a machine-specific Temporal CLI path. `start-stack.ps1` now also looks on PATH and keeps the original default as the last fallback.

Both items were removed from NOT VERIFIED in README.md and docs/failure-semantics.md.
